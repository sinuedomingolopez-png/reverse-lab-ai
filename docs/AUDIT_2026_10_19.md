# Auditoría inicial — 19 de octubre de 2026

Base: aeb2637, versión 0.12.0. Repositorio existente conservado.

## Evidencia inicial
Windows, Python 3.11.9: 177 pruebas unitarias, correctas, 4 omitidas.
TEMP/TMP deben apuntar a una carpeta escribible del workspace en el sandbox de Codex;
la ubicación temporal virtualizada causó cinco PermissionError en os.replace del historial.
No se ha cambiado HistoryStore: la repetición en carpeta permitida pasa.
CLI, tipos y hash, contratos de informes, exportadores y portable tienen pruebas.
Las pruebas de ejecutores falsos NO validan instalaciones de Ghidra o angr.
No se detectaron Java, Ghidra, Rizin ni Cutter en PATH ni Ghidra por variables documentadas.
MCP, LIEF, angr y PyInstaller no estaban instalados al inicio.

## Revisión por componente
- analyzer/workflow/cli: análisis estático y hash streaming compartidos; sin ejecución de muestra.
- GUI y diálogos: tema oscuro, selector de motores, hilos, progreso indeterminado,
  comparación, pseudocódigo, explorador y mapa de llamadas; sin drag/drop ni panel MCP.
- reports/function_browser/call_graph: validación y límites parciales; no inferir semántica
  desde nombres, firmas o diferencias de direcciones.
- history: persistencia voluntaria; no convertir los trabajos MCP en historial automático.
- ollama_adapter: optativo y local; mantener consentimiento explícito.
- Ghidra: headless y tres scripts Java reales; salida acotada al leer exports.
  Logs pueden contener rutas/contenido privado; no retornarlos por MCP.
  La autoprueba acepta listas vacías: reforzar evidencia antes de afirmar validación real.
  Timeout de subprocess no garantiza matar descendientes Java.
- Rizin: solo rz-bin -Ij; faltan secciones, símbolos y análisis de funciones.
- LIEF: solo recognized/format/entrypoint; faltan cabeceras/secciones/importaciones/exportaciones.
  Parse nativo en proceso principal: aislar en el servicio MCP.
- angr: CFGFast subprocess, auto_load_libs=False, sin ejecución simbólica;
  límite de entrada y tiempo, pero no memoria ni árbol completo de procesos;
  stdout se comprueba después de capturarlo, insuficiente como límite de recursos.
- Cutter: lanzamiento externo explícito, sin integración bidireccional.
- MCP/agente/OAuth: inexistentes en la base; no hay conexión ChatGPT.
- portable: constructor onedir, scripts incluidos, motores excluidos, SHA-256,
  diagnóstico offline y GUI; no firmado. Aún no compilado en esta sesión.
- CI: cuatro workflows (tests Windows/Linux Python 3.10/3.13, UI Xvfb,
  motores LIEF Windows/Linux y angr Linux, portable Windows).
  Dependencias no fijadas; faltan contratos y cliente MCP real. Historial de Actions
  pendiente de consulta, leer YAML no demuestra ejecuciones correctas.

## Orden de corrección
1. Enriquecer LIEF y Rizin preservando contratos existentes, añadir pruebas reales opcionales.
2. Servicio de trabajos local: archivos concedidos por hash y raíz, snapshots privados,
   límites de tiempo/memoria/concurrencia/salida, cancelación del árbol de procesos.
3. SDK oficial Python MCP, herramientas estructuradas/paginadas; stdio privado por defecto.
4. HTTP solo loopback, OAuth con proveedor externo y túnel saliente autorizado.
   No transmitir nombres/código/reportes sin concesión local explícita.
5. Probar cliente MCP auténtico con ELF sintético; documentar por separado motores ausentes.
6. UI, portable y comprobación CI. No fusionar cambios sin validación.

Hallazgo adicional confirmado: el workflow real-engines no se estaba registrando
con su nombre. `run: python -m pip install --only-binary=:all: lief` contenía
un segundo `:` seguido de espacio en un escalar YAML sin comillas. Se corrige
el YAML y se añade análisis sintáctico de todos los workflows al pipeline.
Las ejecuciones verdes de Tests/UI/portable no validaban ese workflow roto.
